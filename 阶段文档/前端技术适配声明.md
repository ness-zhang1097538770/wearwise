# 前端技术适配声明

## 1. 项目判断
- 产品类型：AI 穿搭与理性购物助手（数字衣柜 + AIGC 成像 + 购物决策）
- 主要用户：18–40 岁有穿搭需求且常网购的用户
- 主要终端：**移动 Web 优先**（手机浏览器），桌面自适应
- 新项目或已有项目：新项目（后端 MVP 已完成，API 可复用）
- 本阶段业务目标：把临时验收界面换成正式前端，先出代表页（首页）确认视觉，再铺开全部页面

## 2. 输入资料
- PRD：已读取（V2.0）
- 后端手册：已读取
- 接口文档：完整（后端 API 已就绪，见 README）
- 设计稿：**有**（产品经理提供的视觉系统 v1.0，`tokens.css` + index.html）
- 现有代码：有（后端 FastAPI + 临时静态界面）

## 3. 技术选择
- 框架与版本：Next.js（App Router）+ React 19 + TypeScript strict
- 样式与组件策略：Tailwind CSS + 设计 token 落为 `@theme`（直接采用产品经理提供的 tokens.css）
- 数据请求与状态策略：客户端 fetch 直连后端 API（`NEXT_PUBLIC_API_BASE` 可配），SWR/React Query 按需，先用手写 hooks
- 流式通信策略：SSE（穿搭生成/购物分析用 EventSource/fetch stream）；轮询（图片/视频任务用轮询）
- 表单方案：受控组件 + 原生表单校验
- 测试方案：Vitest + React Testing Library（关键组件）+ typecheck + lint
- 部署环境：本地开发；生产沿用 veFaaS（阶段 4）

## 4. Agent 状态
- 后端状态 → 前端统一状态映射：garment(draft/confirmed)、outfit(pending/done/failed)、task(pending/running/done/failed)、avatar(pending/done/failed)
- 等待用户确认方式：衣物识别后 draft → 用户编辑确认；Avatar 4 选 1；穿搭锁定/替换
- 取消、重试、断线恢复方式：任务轮询带超时与重试；页面刷新后从后端恢复任务状态
- 任务 ID 和恢复入口：tasks 表 ID 轮询；生成中页面展示进度

## 5. 页面与产物
- 核心页面：今日（穿搭推荐）、衣橱、试穿（Avatar/上身图/视频）、购物分析、我的（主形象/额度/设置）
- 核心业务闭环：录衣柜 → 今日推荐 → 试穿 → 购物分析
- 产物类型和预览方式：文字方案、图片（平铺图/上身图）、视频（mp4 播放）
- 响应式目标：移动端 375–430px 优先，桌面自适应（最大宽度约 1040px）

## 6. 偏离本手册的地方
- 底部导航：采用设计系统指定的 4 tab（今日/衣橱/试穿/我的）；购物分析作为"今日"页入口或次级页面
- 试穿：WearWise 决策为"仅 Avatar"（不上传真人照片），与设计系统中"我的照片 vs 试穿后"的示例不同——试穿对比改为"Avatar 形象 vs 试穿后"

## 7. 待确认事项
无（决策台账无"待定"项；设计系统已由产品经理提供并确认方向）
