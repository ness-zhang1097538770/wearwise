# 技术适配声明

> 项目：WearWise（AI 穿搭与理性购物助手）
> 产出日期：2026-09-22
> 依据：PRD V2.0、阶段 0 体检结论、通用技术栈手册第一至六节

## 1. 产品形态判断

- **产品类型与核心任务**：AI 穿搭与理性购物助手。核心任务=数字衣柜 + 场景穿搭规划 + 购物防冲动分析 + AIGC 成像（静态图 / 动态视频）。
- **核心交互**：分阶段确认 + 多轮对话（风格测试、形象锁定、单品锁定/替换、成像层级点击触发、冷静期）+ 异步任务（视频生成，提交 → 队列 → 进度 → 通知）。
- **开发路径**：**路径 B 纵向切片**。理由：本产品的"人工确认 + 图片/视频预览 + 异步任务恢复"本身就是核心能力，产出必须"用眼睛看、亲手操作"才能验收，不能等后端全部完成再铺前端。
- **当前阶段范围**：阶段 2 后端 MVP，拆成 3 个子阶段（每条端到端链路跑通后再扩下一条）：
  - **2.1 衣柜与穿搭**：拍照录入 → 衣物识别 → 确认标签 → 生成穿搭（L0 文字 + L1 平铺图）→ 收藏。含最小验收界面。
  - **2.2 AIGC 静态成像**：Avatar 形象生成 → 造型上身图（IMG-03）→ 商品上身图 + 新旧对比图（IMG-07/08）。
  - **2.3 视频与购物分析**：动态试穿视频（VID-01）+ 面料动态（VID-02）异步队列 + 购物防冲动分析报告。

## 2. 采用的默认方案

| 方案 | 采用原因 |
| --- | --- |
| Python 3.12.x + FastAPI | 手册默认后端；与上线运行时一致，接口可测试可调用 |
| Pydantic | 校验接口入参与模型结构化输出 |
| pytest | mock 自动化测试，覆盖业务逻辑与错误路径 |
| Git + .gitignore + .env | 版本管理；密钥不进仓库、不进前端 |
| 官方 SDK / 兼容接口调用模型 | 保证超时、失败、有限重试与 SDK 初始化兜底 |

## 3. 触发的按需模块

| 模块 | 触发需求 | 当前阶段是否引入 |
| --- | --- | --- |
| SQLite + SQLAlchemy + Alembic | 多实体关系（用户、衣柜、衣物、造型、成像任务、生成物）、筛选统计、账户 | **引入**（阶段 2.1） |
| 持久化任务记录 + 后台队列 | 视频生成长耗时（20s–3min）、异步执行、可恢复 | **引入**（阶段 2.3 引入；先用轻量持久化队列，规模阈值后再评估 Redis/Celery） |
| 本地文件目录 | 图片、视频生成物大文件存储 | **引入**（阶段 2.1；生产阶段评估对象存储） |
| SSE（或"提交 + 查询状态"） | 穿搭/成像生成过程逐步展示 | **引入**（阶段 2.1；图用 SSE 展示进度，视频用提交+查询状态） |
| OCR / pypdf / python-docx / Chroma | 无对应需求（衣物识别走多模态视觉模型，非文档 OCR） | **不引入** |

## 4. 偏离或暂缓的默认方案

| 默认方案 | 替代 / 调整 | 原因 | 影响 | 重新评估条件 |
| --- | --- | --- | --- | --- |
| PRD 指定"移动端 App 为主" | 阶段 2/3 先做 Web 版（手机浏览器可用），App 后置 | 决策 D10：先 Web 验证核心价值，避免未验证就铺开 App | 用户只能在浏览器体验，但不影响核心链路验证 | 核心链路验收通过后评估 React Native |
| 手机号短信注册（D5） | MVP 用"游客体验 + 邀请码" | 手机号短信需要短信平台（新增费用/外部平台，PRD 未要求）；<100 人内部试用不需要 | 无短信登录能力，阶段 4 上线前补齐 | 阶段 4 上线前接入短信服务并确认费用 |
| 一致性专用 LoRA 自训 | MVP 用通用参考图控制方案 | 决策：先通用方案，投诉率 >8% 再启动 | 一致性上限略低，但 MVP 够用 | 一致性投诉率 >8% |
| 真人形象通路 | MVP 仅 Avatar | 决策 D10#5：隐私风险低、开发量小 | 无真人上身图，放 V1.5 | V1.5 评估 |
| 对象存储 | MVP 用本地文件目录 | 用户量 <100，本地够用 | 单机存储，无跨机冗余 | 用户量增长 / 上生产前 |
| 自营重队列（Redis/Celery） | MVP 用轻量持久化队列 | 视频任务量小，避免过度引入 | 无水平扩展，单进程够用 | 并发视频任务明显增长时 |

## 5. 强制底线检查

- **密钥与隐私**：通过。本地用 .env（已 gitignore），模型 Key 由产品经理填，不回显；上传文件校验格式/大小/安全文件名；日志不记密钥、密码、完整用户文档。
- **数据与任务可恢复**：通过。SQLite 持久化 + 成像任务记录持久化，进程重启后可恢复；阶段 2.1 起验证。
- **输入输出校验**：通过。Pydantic 校验；模型输出结构校验；错误统一 `{"error":{"code","message"}}`；SSE 以 done/error 收尾。
- **错误与日志边界**：通过。不泄露堆栈；模型调用超时/失败/有限重试 + SDK 初始化兜底。
- **测试与真实模型验收**：mock 自动化测试 + 真实模型冒烟。无 Key 时如实写"待验"；验收前由产品经理补 Key。

## 供产品经理确认的三件事

1. **我理解的产品对不对**：先做 Web 版 MVP，跑通"录衣柜 → 出穿搭（文字+平铺图）→ Avatar 上身图 → 3s 试穿视频 → 购物分析"这条主链路，分 3 个子阶段交付。
2. **是否新增了 PRD 没要求的费用/平台/范围**：本期**不新增**任何付费外部平台（短信登录、对象存储、重队列都暂缓）。唯一要你知道的是：MVP 登录用"游客 + 邀请码"，不接手机号短信。
3. **被暂缓的能力是否影响本阶段验收**：暂缓的是——移动 App、手机号登录、真人上身图、LoRA 自训、对象存储。都不影响"看得到穿搭图/视频、做得了购物判断"的核心验收。
