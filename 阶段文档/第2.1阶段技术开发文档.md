# 第 2.1 阶段技术开发文档｜衣柜与穿搭（拍照录入 → 识别 → 穿搭文字 + 平铺图）

> 配套文档：PRD V2.0、通用技术栈手册、《技术适配声明》（阶段文档/技术适配声明.md）
> 本文档只覆盖第 2.1 阶段，不提前实现 2.2（Avatar/上身图）与 2.3（视频/购物分析）。

## 一、阶段目标

- **交付范围**（对齐 PRD MVP 范围 + 技术适配声明 2.1 切片）：
  - 拍照录入衣物 → AI 识别标签（品类/颜色/图案/材质/版型/季节）→ 人工确认/修正 → 保存进数字衣柜；
  - 生成穿搭方案：L0 文字方案（3 套候选，含推荐理由 + 匹配度）+ L1 平铺图（默认附带）；
  - 锁定/替换单品、收藏造型；
  - 最小验收界面（临时工具，阶段 3 换正式前端）。
- **阶段产物**：可运行的 FastAPI 后端 + 最小验收界面 + mock 自动化测试 + 证据包。
- **验收标准**：
  1. 上传衣物照片，识别出品类/颜色等标签且可人工修正后保存；
  2. 生成 3 套穿搭文字方案，能锁定/替换单品并收藏；
  3. 平铺图生成（L1）——无真实 Key 时如实写"待验"；
  4. 服务重启后衣物与造型数据可恢复；
  5. 最小验收界面能独立完成上述操作。
- **明确不做**：Avatar 形象、造型上身图（L2）、商品上身图/新旧对比图（IMG-07/08）、动态视频、购物分析报告、穿搭日历、衣柜缺口分析、发型妆容、场景沉浸图、登录/多用户（本阶段单用户，无登录）。
- **本阶段打通的主链路片段**：拍照 → 识别 → 确认标签 → 生成穿搭（文字）→ 生成平铺图 → 收藏。

## 二、技术适配摘要

- 引用《技术适配声明》结论：Web MVP、纵向切片、数据全国内、500 元/月封顶、仅 Avatar、先单用户邀请码。
- 本阶段采用默认方案：Python 3.12 + FastAPI + Pydantic + pytest + Git/.env。
- 本阶段启用按需模块：SQLite + SQLAlchemy + Alembic（多实体关系）；本地文件目录（图片资产）；SSE（穿搭文字流式）；"提交+轮询"（平铺图异步）。
- 本阶段偏离/暂缓：手机号登录暂缓（单用户，无登录）；对象存储暂缓（本地目录）；真人形象/Avatar 暂缓（2.2）。
- 开发路径：纵向切片。

## 三、技术栈与模型

- **组件**：FastAPI、SQLAlchemy、Alembic、pytest、python-multipart（上传）、httpx（模型调用）。不引入 Redis/Celery、不引入前端脚手架。
- **模型选型（火山方舟，国内，配置化）**：
  | 用途 | 模型 | 配置项 |
  | --- | --- | --- |
  | 衣物识别（视觉） | 豆包视觉 doubao-1.5-vision-pro | `VISION_MODEL` |
  | 穿搭推荐（文本 LLM） | 豆包 doubao-1.5-pro-32k | `TEXT_MODEL` |
  | 平铺图（图像生成） | 即梦 seedream（火山方舟图像 API） | `IMAGE_MODEL` |
  - 模型名、base_url、超时、参数全部走 `.env`，代码不硬编码；最终模型名以真实 Key 实测为准。

## 六、数据、资产与状态

- **持久化**：SQLite（`data/wardrobe.db`）+ Alembic 迁移。
- **数据表**：
  | 表 | 字段 | 说明 |
  | --- | --- | --- |
  | garments | id, name, category, color, pattern, material, fit, season, style, image_path, tags_json, status(draft/confirmed), created_at | 衣物卡片 |
  | outfits | id, inputs_json(天气/场合/风格), result_json(3套方案), status(pending/done/failed), created_at | 穿搭方案 |
  | tasks | id, kind(image), outfit_id, status(pending/running/done/failed), result_json, error, created_at | 平铺图异步任务 |
- **资产**：衣物照片 `data/uploads/`；平铺图 `data/generated/`；文件名用安全随机名，元数据入库。
- **状态机**：
  - garment: `draft`（识别待确认）→ `confirmed`（用户确认/修正后）；
  - outfit: `pending` → `done` / `failed`；
  - task: `pending` → `running` → `done` / `failed`（失败不扣额度，可重试）。

## 七、API 设计（前缀 `/api/v1`，错误统一 `{"error":{"code","message"}}`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | /api/v1/garments | 上传照片 + 识别，返回 draft 衣物（含标签） |
| GET | /api/v1/garments | 列表/筛选（category/color/status） |
| PATCH | /api/v1/garments/{id} | 修正标签 → confirmed |
| DELETE | /api/v1/garments/{id} | 删除（含图片） |
| POST | /api/v1/outfits | 生成穿搭（SSE：chunk 文字 → done 完整 3 套方案） |
| GET | /api/v1/outfits | 列表 |
| GET | /api/v1/outfits/{id} | 详情 |
| POST | /api/v1/outfits/{id}/items/{idx}/image | 为第 idx 套生成平铺图（提交+轮询，返回 task_id） |
| GET | /api/v1/tasks/{id} | 查平铺图任务状态（done 返回图 URL） |
| POST | /api/v1/outfits/{id}/favorite | 收藏/取消收藏 |

- 上传校验：仅 jpg/png/webp，真实类型嗅探，≤20MB，安全文件名。
- SSE 事件序列：`chunk`（多次）→ `done`（含完整 result）/ `error`（统一错误结构）。

## 八、Prompt 设计

- 独立文件放 `app/services/prompts/`，带版本号与正反例。
- **衣物识别 prompt**：图 → JSON（品类/颜色/图案/材质/版型/季节/风格），正反例 + Pydantic 强校验 + 宽容解析（兼容多种键名/枚举别名）；低置信度标记"建议确认"。
- **穿搭推荐 prompt**：衣柜清单 + 天气/场合/风格 → 3 套方案 JSON（每套：单品 + 理由 + 场景/天气/风格/舒适度匹配分）。数量超 3 套记为瑕疵，不重试。
- **平铺图 prompt**：3–8 件衣物描述 → 杂志感平铺组合图；护栏：禁用"瘦/显瘦/磨皮/美白/滤镜/高级感"等美化词；输出叠加 AI 标识说明（界面层强制展示）。

## 九、验收界面

- `backend/app/static/index.html`，原生 JS + fetch/EventSource，由 FastAPI 挂载。
- 功能：上传照片 → 看识别结果 → 编辑标签保存 → 生成穿搭（流式文字）→ 生成平铺图（轮询）→ 看图 → 收藏。
- 是临时验收工具；因"上传/预览/确认"属于产品核心交互，本切片作为阶段 3 正式前端的第一条纵向切片复用交互逻辑（页面层重构）。

## 十、测试要求

- **第一层 mock 测试（pytest，模型一律 mock，离线可跑）**：
  1. 上传校验（非图片/超 20MB/安全文件名）；
  2. 识别解析器（正常 JSON、字段缺失、枚举别名、错误格式）；
  3. 穿搭方案解析器（同上 + 数量超标）；
  4. 状态流转（draft→confirmed；outfit/task 终态）；
  5. 错误路径（不存在的 id、统一错误结构）；
  6. SSE 收尾（done/error 必居其一）。
- **第二层真实冒烟（无 Key 时"待验"）**：真实照片识别 → 真实穿搭文字 → 真实平铺图，记录模型、耗时、成本、结构合规率；用 `curl -N` 测 SSE 首 chunk 与收尾。

## 十一、验收清单（产品经理照着点）

1. 打开最小验收界面地址（我提供）；
2. 上传 1 张衣服照片 → 看到识别出的品类/颜色等标签；
3. 改一个标签 → 保存成功；
4. 再录 2 件 → 衣柜列表显示 3 件；
5. 点"生成穿搭" → 看到 3 套文字方案（流式出现）；
6. 点其中一套"生成平铺图" → 等到一张组合图（无 Key 时此步"待验"）；
7. 收藏该套造型 → 刷新后仍在；
8. 重启服务 → 衣物和收藏仍在（数据可恢复）。
