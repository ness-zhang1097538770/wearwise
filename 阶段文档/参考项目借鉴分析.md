# 参考项目分析：AIWardrobe 可借鉴点清单

> 参考项目：https://github.com/leoz9/AIWardrobe （AI 智能衣橱）
> 分析日期：2026-09-22
> 目的：提炼可借鉴的设计与实现，评估哪些适合 WearWise。

## 参考项目定位对比

| | AIWardrobe | WearWise |
| --- | --- | --- |
| 核心 | 天气感知穿搭推荐 + 衣橱管理 | 理性购物决策 + AIGC 成像 |
| 推荐方式 | 规则打分 + LLM 写文案 | 纯 LLM 生成 |
| 成像 | 仅可选第三方 Try-On 接口（未实现） | 自研：平铺图/上身图/Avatar/视频 |
| 天气 | 真实天气（Open-Meteo） | 用户手动填 |
| 购物决策 | 简单补购兜底 | 完整的匹配度/重复度/成本分析 |

**结论**：WearWise 在 AIGC 成像和购物决策上更强；AIWardrobe 在"天气感知 + 确定性推荐引擎 + 可解释性"上值得借鉴。

## 可借鉴点（按价值分级）

### ⭐⭐⭐ 强烈建议采纳

**1. 真实天气感知（Open-Meteo，免费无需 Key）**
- AIWardrobe 用 Open-Meteo 免费接口拿实时温度/体感/湿度/风力，并把体感温度分成 5 档（寒冷≤5°C / 偏凉≤14 / 舒适≤24 / 偏热≤30 / 炎热>30），每档有允许季节和穿搭建议。
- 对 WearWise 的价值：穿搭推荐不用再让用户手动填天气，自动感知"今天该穿厚的还是薄的"，推荐更准。
- 成本：0（免费接口），只需本地缓存减少重复请求。

**2. 规则引擎 + LLM 混合（确定性打分 + LLM 写文案）**
- AIWardrobe 先用确定性规则给每件衣服打分（季节匹配、场景匹配、颜色匹配），选出单品，再让 LLM 生成推荐文案；LLM 失败时回退到规则文本。
- 对 WearWise 的价值：
  - 推荐更稳定（不靠模型随机发挥）；
  - 每个单品有明确选择理由（可解释）；
  - 省钱（LLM 只写文案，不做筛选）；
  - 符合"固定流程用代码状态机"的工程底线。
- 这是最值得借鉴的一点。

### ⭐⭐ 可选

**3. 单品级可解释理由**
- 每件单品展示"为什么选它"（季节匹配/场景匹配/颜色协调）。WearWise 目前是整体理由，可细化到单品级。

**4. 补购建议（衣柜缺口提示）**
- 衣柜缺某类温度匹配单品时，给出补购清单（这是 WearWise PRD"衣柜缺口分析"的简化版，可提前在 MVP 落地）。

**5. 本地离线抠图（rembg）**
- 上传后自动去背景，衣物卡片更干净（也有利于平铺图生成）。需额外装 onnxruntime 依赖；WearWise 已有 Seedream 标准平铺图能力，此项价值中等。

### ⭐ 不适合 / 暂缓

**6. 星座运势 / 幸运色**：与 WearWise"理性购物"定位冲突（玄学 vs 理性），不建议采纳。
**7. 语音输入**：PRD 未提，非核心，暂缓。
**8. 多模式推荐（balanced/goal_first/wardrobe_first）**：可作后续增强，MVP 暂不引入。
**9. Liquid Glass UI 风格**：作为阶段 3 正式前端的视觉参考（透明浮层、柔和边框、移动端优先）。

## 推荐采纳方案

- **本轮采纳（阶段 2 增强）**：#1 天气感知 + #2 规则+LLM 混合，这两点直接提升核心推荐质量，成本低。
- **阶段 3 前端落地**：#3 单品理由展示、#9 UI 风格参考。
- **暂缓**：#4 补购建议（放购物分析增强）、#5 抠图、#6 星座、#7 语音、#8 多模式。
