# WearWise 产品需求文档（PRD）V2.0

**产品理念：**先用好已有衣物，再决定是否购买新衣。

> **V2.0 定位：**在 V1.0「数字衣柜 + 理性决策」的基础上，引入 AIGC 成像能力（生图 / 生视频），把「文字描述的搭配方案」升级为「看得见的静态造型图」和「动得起来的动态试穿视频」，让用户**在购买前就能看见、转动、比较**。
>
> **核心约束：**AIGC 在本产品中是**决策证据工具**，不是**美化促销工具**。所有生成物必须比真实更"收敛"，不能比真实更"讨好"。

## 产品概述

WearWise 是一款以数字衣柜为基础的 AI 穿搭与理性购物助手。

用户可以通过拍照、截图、订单导入等方式建立个人数字衣柜。WearWise 根据用户的已有衣物、身材特征、个人风格、天气、场景和日程生成穿搭方案。

**V2.0 新增：**每一次搭配方案都可以通过 AIGC 生成对应的视觉物料——

- **静态：**杂志感平铺图、完整造型上身图、真实场景沉浸图、发型与妆容预览；
- **动态：**转身走动的动态试穿视频、面料垂坠与摆动视频、一周穿搭 Lookbook。

当用户准备购买新衣时，WearWise 会分析该商品与现有衣柜的匹配程度、重复程度、可搭配数量、预计使用频率和单次穿着成本，并**生成该商品穿在用户自己形象上的图与视频**，帮助用户判断商品是否真正值得购买。

产品通过记录用户实际穿着和反馈，不断学习其偏好，逐渐形成个人专属的 AI 造型与成像模型。

## 产品愿景

> 让每一次穿衣更轻松，让每一次购买更理性。
>

WearWise 不以鼓励用户购买更多衣物为目标，而是帮助用户：

- 更充分地利用已有衣物；
- 更快速地完成每日穿搭；
- 更有计划地管理服装消费；
- 更准确地判断新商品是否适合自己；
- **在购买前"看见"真实的自己，而不是模特的样子；**
- 减少冲动消费、闲置衣物和服装浪费；
- 逐步建立稳定且具有个人特色的穿衣风格。

## 用户问题

### 核心痛点

1. 衣柜里有很多衣服，却不知道如何搭配。
2. 不清楚自己已经拥有哪些相似单品。
3. 购买时容易受到模特图、折扣和营销话术影响。
4. 新衣服买回来后，可能无法与现有衣物搭配。
5. 无法准确想象商品穿在自己身上的效果。
6. 旅行、约会、面试等场景需要提前规划穿搭。
7. 衣物使用情况缺乏记录，长期闲置而不自知。
8. 普通穿搭推荐不了解用户真实拥有的衣物。
9. 现有虚拟试衣通常只解决"看起来如何"，没有回答"是否值得买"。

### AIGC 时代新增痛点（V2.0）

10. **文字方案想象成本仍然很高。**"米白针织 + 藏青直筒裤 + 乐福鞋"这句话，多数用户脑中浮现的画面差异极大，导致方案被放弃。
11. **平面图看不出面料行为。**垂坠感、蓬松度、走起来会不会贴腿、风一吹会怎样——静态图完全无法回答，这是"买回来才发现不对"的主要原因之一。
12. **不想上传自己的身体照片。**大量用户因为隐私顾虑，直接放弃虚拟试穿这类功能，产品价值无法兑现。
13. **现有试穿结果"太完美"，反而变成了劝买工具。**平台用精修效果图刺激下单，与"理性消费"完全相反。
14. **知道自己缺一件，却说不清缺什么样的。**无法向搜索框或导购描述"一件能搭我那三条裤子的秋季外套"。

## 目标用户

### 核心用户：高频网购型用户

**特点：**每月至少浏览或购买一次服饰；经常收藏、加购或冲动下单；衣柜中存在较多相似或闲置单品；愿意尝试 AI 推荐和虚拟试穿。

**核心需求：**判断商品是否值得购买；了解新商品能与哪些已有衣物搭配；降低退货率和闲置率。

**AIGC 价值：**动态试穿视频替代想象，面料动效直接暴露"买回来会不会失望"。

### 次级用户：穿搭困难型用户

**特点：**拥有一定数量的衣物；对颜色、版型和风格搭配缺乏信心；每天选择衣服耗时较长。

**核心需求：**快速获得可直接照着穿的方案；根据天气和活动自动规划穿搭；逐渐形成个人风格。

**AIGC 价值：**直接给出"照着穿"的成品图，而不是需要二次翻译的文字清单。

### 潜力用户：计划管理型用户

**特点：**经常出差、旅行或参加正式活动；习惯使用日历、清单等规划工具；希望提前安排一周或整个旅程的穿搭。

**核心需求：**周穿搭日历；行李箱规划；重要场合造型方案。

**AIGC 价值：**一键生成旅行 Lookbook 视频，打包成行李清单与每日造型对照。

### 新增用户：隐私敏感型用户（V2.0 覆盖）

**特点：**认可虚拟试穿价值，但拒绝上传本人全身照片。

**核心需求：**在不暴露真实身体的前提下获得上身参考。

**AIGC 价值：**通过身高、体型、肤色、发色生成专属**数字形象 Avatar**，全部成像在 Avatar 上完成，永不触碰真人照片。

## 产品目标

### MVP 目标

1. 验证用户愿意投入时间建立基础数字衣柜。
2. 验证基于真实衣柜生成的穿搭建议，比通用穿搭推荐更有价值。
3. 验证购买前的匹配与重复分析能够影响用户的购买决策。
4. **验证 AIGC 成像（图 / 视频）能显著提升穿搭方案采纳率与购物决策满意度。**
5. **验证"收敛式生成"不会反向推高购买率——即 AIGC 让决策更准，而不是让用户更想买。**

### 商业目标

- 建立高质量的用户衣柜与风格数据；
- 提高用户周活跃率和穿搭方案采纳率；
- 通过订阅服务实现收入；
- **通过 AIGC 生成额度形成清晰的付费分层；**
- 后续探索电商导购、品牌合作和衣物循环服务；
- 保持推荐结果的可信度和独立性。

### 非目标

MVP 阶段暂不重点解决：自营服装电商、服装设计与生产、社交内容社区、二手服饰交易、专业造型师在线咨询，以及极高精度的布料物理仿真。

**AIGC 相关非目标：**

- 不做"通用 AI 写真 / 换脸娱乐"类功能，与产品定位无关；
- 不做高保真布料物理引擎仿真（CLO 3D 级别），采用视频生成的视觉近似替代；
- 不承诺生成结果与实物 100% 一致；
- 不生成过度美化、改变体型或带有性暗示的成像内容。

## 核心价值主张

### 今天穿什么？

根据天气、场景、日程和个人偏好，从已有衣柜中生成完整穿搭。

### 这件衣服值得买吗？

判断商品是否与已有衣物匹配、是否重复、能搭配多少套，以及买回来后可能穿几次。

### 它穿在我身上怎么样？

通过虚拟试穿和完整造型预览，展示服装、发型、配饰组合后的整体效果。

### 它动起来是什么样？（V2.0 新增）

通过 AIGC 视频，看清面料的垂坠与摆动、走动时的整体廓形、转身后的背面效果——**把"买回来才发现"提前到"买之前就看见"**。

## 产品原则

1. 优先使用用户已有衣物。
2. 每项 AI 建议都尽量说明原因。
3. 不用单一审美标准评价用户身体。
4. 不通过制造身材焦虑促进消费。
5. 商业推荐与独立建议必须明确区分。
6. 用户可以修改 AI 识别结果和推荐偏好。
7. 用户对身体照片和衣柜数据拥有控制权。
8. 推荐同时考虑美观、舒适、场景和实际可执行性。

### AIGC 专项原则（V2.0 新增）

9. **生成必须收敛，不得美化。**不允许自动瘦脸、瘦身、拉长比例、磨皮、改善体态。生成物是"参考"，不是"理想化的你"。
10. **生成物必须可溯源。**每张图、每条视频都标注：AI 生成、使用的基础素材（真人身材 / Avatar）、不作为尺码与实物依据。
11. **不得用生成结果做情感劝买。**禁止在生成物上叠加"太好看了""必入""错过可惜"类文案。生成物旁边只能出现中性的决策信息。
12. **真人照片默认不用于训练。**用户可显式授权，且可随时撤回。
13. **用户始终拥有不生成的选择。**所有成像功能均可跳过，文字方案永远完整可用。
14. **生成失败不惩罚用户。**失败、超时、质量不达标均不扣除额度。

## 核心功能需求

### 1. 用户风格档案

**功能目标：**建立用户的个人穿搭模型，为推荐、购物分析和虚拟试穿提供基础。

**用户信息：**身高、体重、常穿尺码、身材特征、肤色与发色、喜欢或不喜欢的颜色、喜欢的风格、常见穿着场景、舒适度偏好、搭配大胆程度、服装预算、所在城市和穿衣限制。非必要身体信息均为可选。

**风格初始化：**通过快速问卷，或从多组穿搭图片中选择"喜欢/不喜欢"。

**V2.0 新增字段：**成像偏好（是否使用 Avatar / 真人照片 / 平铺模式）、形象一致性偏好（是否固定发型、妆容浓度）、生成风格偏好（写实 / 杂志感 / 极简棚拍）、是否允许生成视频。

**验收标准：**用户可在 3 分钟内完成初始设置；所有非必要身体信息均可跳过；偏好可随时修改；AI 明确展示其理解的风格标签。

### 2. 数字衣柜

**功能目标：**将用户真实拥有的衣物结构化，为穿搭推荐、购买分析和 AIGC 成像提供数据基础。

**录入方式：**

- **拍照录入：**自动移除背景，识别品类、颜色、图案、材质、季节、版型、风格和场景。
- **批量录入：**连续拍摄多件衣物，批量识别并集中确认。
- **商品截图录入：**提取商品主体并生成衣物卡片。
- **订单导入：**后续在用户授权后从邮箱或支持的电商订单导入。

**衣物卡片字段：**名称、图片、品类、品牌、颜色、图案、材质、版型、尺码、季节、场景、价格、购买日期、穿着次数、最近穿着日期、清洁状态、收藏状态、自定义标签和是否愿意再次购买。

**V2.0 新增字段：**

- **视觉指纹 ID（garment embedding）：**每件衣物生成一次视觉向量，供后续所有成像复用，保证同一件衣服在不同造型中出现时外观一致。
- **标准平铺图：**录入时自动生成一张干净的白底平铺图，作为成像的标准参考素材。
- **成像可用状态：**标记该衣物是否适合作为成像参考（图片模糊、褶皱严重、透视装等会被标记为"建议重拍"）。

**衣柜管理：**支持搜索、筛选、编辑、删除、收藏、清洁状态、分类浏览、闲置衣物和利用率统计。

**验收标准：**单件平均录入时间不超过 20 秒；支持一键确认；AI 标签可编辑；背景移除失败时保留原图；低置信度结果提示用户确认；**标准平铺图生成成功率 ≥ 90%**。

### 3. AI 场景穿搭导演

**功能目标：**根据真实衣柜和具体场景生成可执行的完整造型。

**输入：**日期、地点、天气、活动、正式程度、室内外、步行量、希望传达的感觉、必须或禁止使用的单品，以及是否允许推荐待购商品。

**典型场景：**日常通勤、商务会议、面试、约会、朋友聚会、婚礼、旅行、运动、演讲、音乐节和临时天气变化。

**输出：**每次生成 3 套候选，包含上装、下装、外套、鞋、包、配饰、发型、可选妆容、效果图、推荐理由，以及天气、场景、舒适度和风格匹配度。

**V2.0 输出升级：**

| 层级 | 内容 | 生成方式 | 说明 |
| --- | --- | --- | --- |
| L0 文字方案 | 单品清单 + 推荐理由 | 规则 + LLM | 永远可用，零成本，秒出 |
| L1 平铺图 | 杂志感平铺组合图 | 生图 | 默认自动附带，成本极低 |
| L2 造型上身图 | Avatar 或真人上身完整造型 | 生图 | 用户点击生成，主推形态 |
| L3 场景沉浸图 | 把造型放进真实场景 | 生图 | 重要场合（面试/婚礼/旅行）使用 |
| L4 动态试穿视频 | 转身 / 走动 / 面料摆动 | 生视频 | Plus 用户，异步生成 |

**交互：**锁定或替换单品、切换发型、调整正式与保暖程度、选择更大胆或更低调、收藏造型、加入穿搭日历、标记实际穿着、**选择成像层级（L0–L4）**、**对生成结果点"重生成 / 不像 / 不像这件衣服"**。

### 4. 穿搭日历

**功能目标：**帮助用户提前数天或数周规划着装。

- 日、周、月视图；
- 将推荐造型拖入指定日期；
- 天气变化提醒；
- 自动识别重复穿搭；
- 衣物清洗和准备提醒；
- 旅行模式与重要活动 countdown；
- 后续支持个人日历同步。

**V2.0 新增：**周视图 / 旅行模式支持一键生成 **Lookbook 视频**（7 套造型连续播放，每套 2–3 秒，配场景标签与天气信息），可导出分享或仅本地保存。

AI 应综合当地天气、日程场景、衣物状态、连续多日差异性、重复使用偏好及行李限制。用户可一键生成未来 7 天穿搭；天气明显变化时只提示调整，不直接覆盖原计划。

### 5. AI 购物防冲动助手

**功能目标：**在用户购买服装之前，给出独立、可解释的价值判断。

**商品输入：**MVP 支持截图、照片、商品链接和手动输入；后续支持浏览器插件、系统分享和电商页面悬浮分析。

| 分析维度 | 说明 |
| --- | --- |
| 衣柜匹配度 | 新商品可以与多少件已有衣物搭配 |
| 可生成造型数 | 至少展示 3 套由新商品和已有衣物构成的造型 |
| 重复度 | 判断是否已有颜色、版型或功能相似的单品 |
| 场景覆盖度 | 判断是否满足尚未覆盖的真实场景 |
| 预计穿着次数 | 根据生活方式、天气和同类衣物使用情况估算 |
| 单次穿着成本 | 商品价格 ÷ 预计穿着次数，并明确标注为预测结果 |
| 风格匹配度 | 判断商品与用户长期偏好的契合程度 |
| 衣柜增益 | 判断商品能否明显增加现有衣物的搭配可能性 |

**V2.0 新增维度：**

| 新增维度 | 说明 |
| --- | --- |
| 上身成像对比 | 生成新商品上身图，与"已有最相似单品"的上身图并排展示，直观回答"我是不是已经有了一件差不多的" |
| 面料动态参考 | 对标注面料生成短视频，展示垂坠/蓬松/摆动行为，暴露"图片看着挺括、实物软塌"类落差 |
| 成像落差提示 | 若商品链接含模特图，明确提示"模特图经过布光、修图与体型差异处理，以下为你形象下的参考效果" |

**决策结果：**采用中性表达，包括"值得考虑""建议等待""与现有衣物较为重复""搭配空间有限""建议先试穿""寻找更合适的替代款"。

**冷静期：**支持 24 小时、48 小时和 7 天愿望清单。结束后询问用户是否仍想购买、是否有明确使用场景、是否已有替代品，以及是否接受预计单次穿着成本。

### 6. 衣柜缺口分析

**功能目标：**区分"真正需要的衣物"和"被营销制造的需求"。

系统根据常见场景、穿搭失败记录、经常缺少的品类、现有衣物搭配连接度、季节变化、穿着频率和用户目标生成缺口清单，包含建议品类、颜色、版型、可适配已有衣物、可增加造型数、预算、优先级和是否建议立即购买。

**V2.0 新增：缺口概念示意图（Concept Image）**

为每个缺口生成一张**中性、无品牌、无模特脸**的概念示意图，用于帮用户把"我缺一件外套"变成"我缺一件这个样子、这个长度、这个颜色的外套"。

- 白底或纯色背景，突出廓形与颜色；
- 不出现品牌 Logo、不出现真人面容；
- 标注为"概念示意，非具体商品推荐"；
- 可直接作为后续商品搜索的视觉筛选锚点（以图搜图）。

不得仅依据潮流制造缺口；必须说明推荐依据；赞助商品不得改变缺口判断；用户可标记"我不需要这个品类"。

### 7. AIGC 成像中心（原"虚拟试穿"升级）

**功能目标：**让用户在购买前，以静态图像和动态视频两种媒介，预览新商品与个人形象及已有衣物的组合效果。

成像中心提供三条并行的形象通路，用户可随时切换：

| 通路 | 输入 | 适用人群 | 隐私等级 | 真实度 |
| --- | --- | --- | --- | --- |
| A. Avatar 形象 | 身高/体型/肤色/发色/风格偏好 → 生成专属数字形象 | 不想上传照片的用户（默认推荐） | 高（不涉及真人照片） | 中（形象近似，非本人） |
| B. 真人形象 | 1 张用户全身正面照（可选侧面） | 追求高真实度的用户 | 中（敏感数据分级管理） | 高（本人外观） |
| C. 平铺模式 | 无需任何形象 | 只想看搭配关系的用户 | 极高 | 低（无上身效果） |

#### 7.1 数字形象 Avatar（V2.0 核心新增）

**生成流程：**

1. 用户填写体型参数（身高、体重区间、肩宽/腰/臀比例倾向、肤色、发色发型、年龄区间）——全部可选，可跳过；
2. 选择形象风格：写实 / 半写实插画 / 极简线稿；
3. 系统生成 4 个候选形象，用户选择 1 个并锁定为**主形象**；
4. 主形象生成视觉指纹并持久化，后续所有成像复用，保证跨造型一致性；
5. 用户可随时微调（发型、发色、妆容浓度、体型参数）并重新生成，历史形象可保留 1 个备选。

**硬性约束：**

- 不接受"变美"类指令：不得生成比用户填写参数更瘦、更高、更白的效果；
- 不生成面部写实肖像：Avatar 默认面部简化处理（避免生成"另一个人的脸"带来的身份与伦理风险）；
- 用户填写的体型参数即为生成上限，系统不得自行优化；
- 一个账号仅允许存在 1 个主形象 + 1 个备选，避免形象滥用。

**验收标准：**从填写到获得可用形象 ≤ 2 分钟；同一形象在 10 次不同造型生成中的外观一致性评分 ≥ 4/5（人工抽检）；用户可一键删除形象及其全部衍生生成物。

**视频能力设计要点：**

- 视频生成成本高、耗时长（通常 20s–3min），**必须异步执行**：提交 → 队列 → 进度提示 → 推送/站内通知 → 结果入库；
- 用户提交后可离开页面，返回时任务继续；
- 视频默认保存 30 天后自动清理（可手动收藏永久保留），控制存储成本；
- 每条视频首帧复用对应的静态造型图，保证图文一致性。

#### 7.4 成像一致性要求

这是 AIGC 成像能否成立的技术底线。用户如果发现"我的衣柜里那件蓝色衬衫，每次生成长得都不一样"，信任会立刻崩塌。

| 一致性对象 | 控制手段 | 验收标准 |
| --- | --- | --- |
| 同一件衣物 | 衣物视觉指纹（garment embedding）+ 参考图条件注入（IP-Adapter / 参考图控制） | 同一衣物在 ≥ 5 次独立生成中，颜色/印花/廓形识别一致率 ≥ 90% |
| 同一个形象 | 形象视觉指纹 + 固定形象参考图 | 同一形象在 ≥ 10 次生成中，体型/肤色/发型一致率 ≥ 90% |
| 图文一致性 | 视频首帧与静态图对齐；造型清单与图中单品一一对应 | 人工抽检错位率 ≤ 5% |
| 品牌与印花 | 印花、格纹、条纹方向需与实物一致；不得凭空生成品牌 Logo | 逻辑错误率 ≤ 3% |

若一致性不达标，产品策略是**降级到低层级成像**（如从 L2 上身图降级到 L1 平铺图），而不是硬出一张不对的图。

### 8. 穿着记录与反馈学习

**功能目标：**通过真实行为而非单纯点赞，持续优化推荐。

**记录方式：**点击"今天穿这套"、日历提醒确认、上传当天照片或手动选择所穿衣物。

**反馈：**喜欢、不喜欢、太冷、太热、不舒服、太正式、太随意、配色不喜欢、实际效果很好、希望多推荐类似风格。

**V2.0 新增反馈：**"**实物与生成效果差异大**"（点击后展开：颜色差异 / 面料垂感差异 / 版型差异 / 上身效果差异）。这是最有价值的 AIGC 反馈信号——用于反向校准成像 prompt，也用于计算**各品类成像可信度指数**。

系统根据采纳、穿着次数、修改、替换、收藏、跳过、舒适度、购买后是否真实穿着及退货闲置情况调整推荐；用户可查看和修改 AI 总结出的偏好。

## AIGC 真实性护栏（V2.0 核心设计）

**问题定义：**AIGC 天然会让画面更好看。一个"穿上显得很美"的生成结果，会直接推高购买率——这与 WearWise 的产品使命正面冲突。如果不加约束，AIGC 会把产品从"防冲动助手"改造成"最强劝买工具"。

**设计目标：**让 AIGC 提高**判断准确度**，而不是提高**购买欲望**。

### 护栏机制

| 机制 | 具体规则 |
| --- | --- |
| 禁用美化词 | 成像 prompt 黑名单：瘦、显瘦、修长、完美身材、大长腿、磨皮、美白、滤镜、高级感（用于人体时） |
| 参数硬约束 | 体型、肤色、身高等参数严格来自用户档案，模型不得"优化"；生成后做一次参数一致性校验 |
| 中性呈现 | 生成图默认不做精调打光与氛围渲染；场景图允许氛围，但人体部分保持中性 |
| 文案隔离 | 生成物周围禁止出现劝买文案、"限时"、倒计时、优惠券弹窗 |
| 强制声明 | 每个成像结果固定叠加：①「AI 生成参考图」角标 ②「非实物效果，不作为尺码与材质依据」小字 ③ 材质/颜色以商品页为准 |
| 并排对照 | 商品上身图必须与「已有最相似单品上身图」并排出现，且相似度高于阈值时，视觉上强化"你已经有类似的了" |
| 落差披露 | 若用户反馈"实物与生成差异大"，系统记录并在该品类/该面料上降低成像置信度提示，如实告知用户"此类面料成像参考度较低" |
| 决策不绑定 | 生成视频完成后，CTA 只能是"加入冷静期 / 加入愿望清单 / 查看分析报告"，不出现"立即购买"按钮 |

### 效果验证指标（护栏是否奏效）

- **护栏组 vs 无护栏组**的 7 日购买转化率：护栏组应显著更低或持平；
- 生成后 30 天实际穿着率：护栏组应更高（说明买得更准）；
- 退货率：护栏组应更低；
- 用户主观调研："这个生成结果让你更想买了，还是更确定不买了？"

## AIGC 技术架构

### 分层结构

```
┌─ 应用层 ────────────────────────────────────────┐
│  穿搭推荐 / 购物分析 / 日历 / 成像中心            │
└────────────────┬────────────────────────────────┘
┌─ 编排层 ───────┴────────────────────────────────┐
│  Prompt 编译器：结构化衣柜 JSON → 成像 Prompt     │
│  一致性控制器：注入形象指纹 / 衣物指纹             │
│  护栏过滤器：美化词黑名单 + 参数校验               │
│  质量评估器：生成后打分，不达标自动重试             │
└────────────────┬────────────────────────────────┘
┌─ 路由层 ───────┴────────────────────────────────┐
│  多模型路由（图像 A/B/C，视频 X/Y）                │
│  按成本、时延、质量分动态选择                      │
│  失败自动切换供应商 + 降级                        │
└────────────────┬────────────────────────────────┘
┌─ 执行层 ───────┴────────────────────────────────┐
│  同步队列（图像，目标 < 8s）                      │
│  异步队列（视频，目标 < 90s）                      │
│  结果缓存 / 对象存储 / CDN                        │
└─────────────────────────────────────────────────┘
```

### 关键模块说明

| 模块 | 职责 | 要点 |
| --- | --- | --- |
| Prompt 编译器 | 把结构化数据（品类、颜色、材质、版型、场景、光照）编译为稳定 Prompt | 模板化 + 版本管理，可 A/B；避免自由发挥导致不一致 |
| 一致性控制器 | 注入形象指纹与衣物指纹参考图 | 图像用参考图条件控制；视频以静态结果作首帧锚定 |
| 护栏过滤器 | 前置拦截美化词，后置校验体型参数 | 双端校验，任一失败即重生成 |
| 质量评估器 | 对生成结果自动打分（一致性、畸变、暴露度、手部/肢体异常） | 低于阈值自动重试一次，仍不达标则降级并告知用户 |
| 多模型路由 | 供应商选型与切换 | 至少接 2 家图像 + 2 家视频供应商，避免单点依赖 |
| 异步任务中心 | 视频队列、进度、通知、超时 | 超时（> 3min）自动取消并不扣额度 |

### 性能与时延目标

| 类型 | 目标时延 | 超时策略 |
| --- | --- | --- |
| 单品平铺图 | ≤ 5s | 超时转原图，不报错 |
| 搭配平铺图 | ≤ 8s | 超时转 L0 文字方案 |
| 造型上身图 | ≤ 12s | 重试 1 次，仍失败降级到平铺图 |
| 动态试穿视频 | ≤ 90s | 异步 + 通知，3min 超时取消 |
| Lookbook 视频 | ≤ 180s | 异步 + 通知，5min 超时取消 |

### 降级链路

```
L4 动态视频   ─失败→  L2 造型上身图
L3 场景沉浸图 ─失败→  L2 造型上身图
L2 造型上身图 ─失败→  L1 搭配平铺图
L1 搭配平铺图 ─失败→  L0 文字方案（永不失败）
```

**原则：**任何一层失败，都必须向下提供可用的东西，且全程不扣额度。

## AIGC 内容安全与合规

| 风险 | 控制措施 |
| --- | --- |
| 生成暴露 / 性化内容 | 输入侧：服装品类白名单，内衣/泳装类目限制成像模式（仅平铺）；输出侧：暴露度检测模型拦截 |

## AIGC 额度与定价

### 额度体系

| 层级 | 静态成像 | 动态视频 | Avatar 形象 | 说明 |
| --- | --- | --- | --- | --- |
| 免费 | 15 张/月 | 2 条/月 | 生成 1 次，不可微调 | 用于体验价值 |
| Plus 月付 | 200 张/月 | 40 条/月 | 无限次微调 | 主力套餐 |
| Plus 年付 | 300 张/月 | 60 条/月 | 无限次微调 | 提升留存 |
| 加量包 | 50 张 / ¥定价待定 | 10 条 / ¥定价待定 | — | 超额购买 |

**额度规则：**

- 失败 / 超时 / 质量不达标 / 用户点"不像" → **一律不扣额度**；
- 缓存命中 → **不扣额度**；
- 额度仅统计"成功交付的成像"；
- 月末未用完的静态额度可结转 50%（视频不结转，成本过高）。

### 定价待决策项

- 视频是否单独计价（按条 vs 按秒）；
- 是否推出"成像日卡"（某天要参加重要活动，临时买 10 条视频额度）；
- 免费额度是否随衣柜完整度动态提升（激励录入）。

## 核心用户流程

### 新用户首次使用

1. 注册或游客体验。
2. 选择主要使用目标。
3. 完成快速风格测试。
4. 设置常见场景与偏好。
5. **选择成像通路（Avatar / 真人照片 / 平铺，可跳过）。**
6. 录入首批 5～10 件衣物（自动生成标准平铺图）。
7. AI 生成第一组穿搭，**默认附带平铺图**。
8. **引导生成第一张造型上身图（首次免费且不占额度）。**
9. 用户收藏或调整。
10. 引导继续完善数字衣柜。

关键要求：用户不应在体验到价值之前，被迫完整录入整个衣柜；**也不应被迫上传照片或设置形象才能使用**。

### 每日穿搭流程

1. 打开首页。
2. 读取天气和当天场景。
3. 展示 3 套推荐（含平铺图）。
4. 锁定、替换或重新生成。
5. **点开某套 → 选择成像层级（上身图 / 场景图 / 动态视频）。**
6. 选择一套并记录穿着。
7. 当天晚些时候邀请轻量反馈（含"实物与生成差异"选项）。

### 购买前分析流程

1. 上传截图或分享商品链接。
2. AI 提取并由用户确认商品信息。
3. 与数字衣柜匹配。
4. 输出购买分析报告。
5. 展示与已有衣物组成的造型（平铺图）。
6. **生成商品上身图 + 与最相似已有单品的对比图。**
7. **（可选）生成面料动态视频。**
8. 发起动态试穿（异步）。
9. 选择购买、等待或放弃。
10. 购买后加入衣柜并追踪实际穿着。
11. **30 天后回收"实物与生成差异"反馈，用于校准该类目成像可信度。**

### 一周穿搭规划流程

1. 选择规划日期。
2. 获取天气和场景。
3. 生成一周穿搭（含每日平铺图）。
4. 调整指定日期并保存。
5. **一键生成 Lookbook 视频（异步，完成后通知）。**
6. 提前提醒准备或清洗衣物。
7. 天气变化时建议重新规划。

## AI 能力设计

| 模块 | 主要能力 |
| --- | --- |
| 服装视觉识别 | 品类、颜色、图案、材质、版型识别 |
| 商品信息解析 | 从截图、图片或链接提取商品数据 |
| 搭配推荐模型 | 基于衣柜、场景、天气和个人偏好组合 |
| 风格理解模型 | 建立并更新用户风格画像 |
| 购物决策模型 | 计算重复度、匹配度、衣柜增益和预计使用率 |
| 图像生成模型 | 虚拟试穿、平铺图、场景图、发型妆容、概念示意图 |
| **视频生成模型** | 动态试穿、面料动态、Lookbook、教程视频 |
| **形象生成与一致性控制** | Avatar 生成、形象指纹、衣物指纹、跨次一致性维持 |
| **生成质量评估** | 畸变检测、一致性打分、暴露度检测、自动重试 |
| 自然语言模型 | 理解场景描述并解释推荐原因 |
| 反馈学习系统 | 根据真实穿着和决策持续优化推荐 |

**推荐总分建议：**场景适配 25% + 天气适配 20% + 风格匹配 20% + 舒适度 15% + 衣物可用性 10% + 利用率提升 10%。权重允许根据用户行为动态调整。

**可解释性：**每项推荐至少给出 2～3 条原因，包括场景、天气、偏好、闲置衣物使用或购买判断。避免"你不适合穿红色"等没有依据的绝对判断。

**成像可信度指数（V2.0）：**按「品类 × 面料 × 供应商」维度统计用户"实物与生成差异"反馈，产出 0–100 的可信度分。低于 60 分时，在该类成像上显示"此类效果参考度较低"提示，并建议优先参考平铺图与文字描述。

## 隐私与安全

WearWise 将处理身体照片、消费记录和穿衣偏好，因此隐私必须作为核心产品能力。

- 明确说明数据用途；
- 身体照片与普通衣物照片分级管理；
- 默认不使用用户照片训练模型；
- 支持删除单张照片、清空衣柜、导出数据和注销账号；
- 第三方图像生成服务数据隔离；
- 敏感数据传输和存储加密；
- 未成年人使用时增加保护措施。

**AIGC 补充条款：**

- **Avatar 通路不采集任何真人照片**，仅使用参数化体型数据；
- 真人形象通路的原图与衍生生成物**分别存储、分别删除权限**，删除原图时提示是否一并删除全部衍生图；
- 第三方生成服务调用时，**仅传输必要的最小图像集**，禁止透传用户身份标识；
- 生成结果的存储默认 30 天自动清理（收藏除外），用户可设置更短周期；
- 用户可导出全部生成物，也可一键清空；
- **用户可随时关闭成像功能**，关闭后产品完全以文字 + 平铺模式运行。

**禁止：**推断或评价用户健康状况；使用羞辱性身材描述；未经允许生成过度暴露图像；将身体照片用于广告；出售衣柜或消费数据；**在用户未授权情况下用生成结果做任何对外展示或营销素材**。

## 异常场景

| 异常情况 | 处理方式 |
| --- | --- |
| 衣物识别错误 | 允许修改，保留反馈用于优化 |
| 图片背景复杂 | 提示重新拍摄或手动裁剪 |
| 商品链接无法解析 | 转为截图或手动输入 |
| 天气数据不可用 | 使用用户手动输入的温度和天气 |
| 可搭配衣物不足 | 明确提示并给出最小补充建议 |
| 虚拟试穿失败 | 不扣除生成次数并提示更换照片 |
| AI 推荐不合适 | 提供快速原因反馈和重新生成 |
| 衣物待洗 | 默认不加入近期推荐 |
| 缺少身体照片 | 仍可使用平铺式搭配预览 |
| 新用户衣物太少 | 使用体验衣柜演示，再引导录入真实衣物 |
| **成像结果不像本人 / 不像该衣物** | 提供"不像"一键反馈，自动重试一次；仍不满意可换形象或降级到平铺图，不扣额度 |
| **生成出现肢体畸变 / 衣物结构错误** | 质量评估器拦截自动重生成；连续失败降级到低层级成像 |
| **视频生成超时** | 3 分钟自动取消，推送告知，不扣额度，赠送一次优先队列 |
| **队列拥塞，等待超过 5 分钟** | 显示队列位置与预估时间，提供"完成后通知我"，允许取消 |
| **衣物照片质量不足以做参考** | 标记"建议重拍"，仍可尝试但提示结果可能不准 |
| **额度用尽** | 明确展示额度消耗明细与重置时间，提供加量包，不做强打断 |
| **供应商整体不可用** | 自动切换备用供应商；全部不可用时，成像入口置灰并保留文字方案完整可用 |
| **用户上传疑似他人照片** | 协议拦截提示 + 人工举报入口 + 违规封禁策略 |

## 主要风险与应对策略

### 录入成本过高

先录入 5 件即可体验；支持批量识别、截图和订单导入；通过搭配任务逐步完善衣柜。

### 推荐结果缺乏信任

给出推荐理由；允许锁定和替换；结合天气、场景和实际衣物；记录用户不喜欢的原因。

### 虚拟试穿不真实

明确效果图是风格参考；区分视觉效果和尺码建议；避免夸大物理仿真能力；**上线成像可信度指数，如实告知哪类目成像参考价值低**。

### 推荐与商业利益冲突

购物判断与商品排序分离；赞助内容明确标识；保留建议不购买的能力；优先推荐现有衣物；**品牌不得介入成像 prompt**。

### 身体形象与审美偏见

使用中性描述；不对身体评分；允许用户定义美学目标；建立生成结果审核和举报机制。

### AIGC 新增风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| **AIGC 反向刺激消费** | 动摇产品使命，用户信任崩塌 | 真实性护栏全套机制 + 护栏效果 A/B 验证 |
| **生成一致性不达标** | 用户发现"衣服每次不一样"，功能失去意义 | 指纹 + 参考图控制；不达标即降级；必要时候训专用 LoRA |
| **视频成本失控** | 毛利被吃穿 | 分层默认、缓存复用、异步削峰、额度上限、成本告警 |
| **供应商单点依赖 / 涨价** | 服务中断或成本剧变 | 至少 2+2 供应商路由，季度比价，保留自建微调的退路 |
| **生成内容合规事故** | 下架、舆论、法律风险 | 前后双审核 + 品类白名单 + 未成年人限制 + 举报机制 |
| **时延过长导致流失** | 用户等待放弃 | 异步 + 通知 + 队列位置可见；先用静态图兜住体验 |
| **"AI 生成"污名化** | 用户认为"假的东西没用" | 明确成像定位为"参考"而非"真实"；用可信度指数量化说明；持续降低差异率 |

## 上线标准

- 主要功能流程无阻断；
- 衣物识别结果可人工修正；
- 推荐理由可正常生成；
- 用户可删除照片和账户数据；
- 虚拟试穿有清晰的效果声明；
- 购物报告中的预测数字标注为估算值；

- 完成敏感图片与不当内容测试；
- 完成基础性能和压力测试；
- 无严重隐私与安全问题；

**AIGC 补充上线标准：**

- 静态图 P95 时延 ≤ 12s，视频 P95 时延 ≤ 120s；
- 生成成功率 ≥ 95%（图）/ ≥ 90%（视频，含重试）；
- 一致性人工抽检合格（衣物 ≥ 90%、形象 ≥ 90%）；
- 美化词黑名单与参数校验 100% 覆盖成像通路；
- AI 生成标识在 App 内、导出图、导出视频三处均不可绕过；
- 护栏 A/B 实验方案已就绪并可灰度；
- 至少 2 家图像 + 2 家视频供应商完成接入与切换演练；
- 成本监控看板与额度熔断机制上线；
- 未成年人账号成像限制验证通过；
- 生成失败 / 超时全部不扣额度的逻辑验证通过。

## 产品差异化

| 普通产品 | WearWise |
| --- | --- |
| 推荐平台正在销售的商品 | 优先推荐用户已经拥有的衣物 |
| 主要帮助用户"买什么" | 同时判断"是否应该买" |
| 只展示单件试穿效果 | 展示新商品与整个衣柜的关系 |
| 推荐依据不透明 | 解释场景、天气、风格和重复度 |
| 用户使用一次即结束 | 根据真实穿着持续学习 |
| 鼓励更多消费 | 提升衣柜利用率并减少浪费 |
| **试穿必须上传本人照片** | **Avatar 形象通路，零照片也能试穿** |
| **只有静态试穿图** | **图 + 视频双通道，看得见面料动态与转身效果** |
| **AIGC 用来让商品更诱人** | **AIGC 用来让判断更准确（真实性护栏）** |
| **生成结果无法验证** | **成像可信度指数 + 实物差异反馈闭环** |

WearWise 最重要的产品壁垒不是单次生成效果，而是随着时间积累形成的：

> **个人衣柜数据 + 穿着行为数据 + 购物决策数据 + 风格偏好模型 + 实物差异校准数据**

数据越完整，推荐越准确、成像越可信，用户迁移成本和产品价值也会随之提升。
